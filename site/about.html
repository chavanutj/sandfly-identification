About this site and how to edit it

The website is generated from plain CSV files. Edit the data, run two commands, and the pages are rebuilt. No database or server is needed.

Files

FileWhat it holds
data/transcriptions/*.txtThe keys, one lead per line, word for word from the source. Edit keys here.
data/transcriptions/_update_notes.txtNotes from later literature attached to particular leads (shown in blue).
data/keys.csvGenerated from the transcriptions. One row per lead: key_id, couplet, lead, text, goto, taxon, group, figures, note, update_note. Opens in Excel.
data/keys_index.csvTitle, source, region and start couplet of each key.
data/taxa.csvOne row per accepted taxon: author, classification, status, distribution, focus-country record (focus_record), medical and diagnostic notes, figures, sources. Edit species pages here.
data/conflicts.csvDisagreements between sources (taxon, character, source A/B, type, comment, status). Shown on species pages and the Conflicts page.
data/glossary.csvTerms used in the keys, preferred terms and synonyms, definitions, figures.
data/sources.csvReferences and licences.
data/figures.csvGenerated by scripts/extract_figures.py from the CC BY PDFs.

Transcription format

27a | Pharyngeal armature with antero-median numerous long pointed teeth ... | | Phlebotomus stantoni | | Lewis 1978 p. 248
27b | Pharyngeal armature with several antero-median rows ...                 | | Phlebotomus hoepplii | | Lewis 1978 p. 247
30a | Paramere with three lobes ... Spermatheca with differentiated end-segment | 31 | | Subgenus Euphlebotomus |
     lead | character text | go to couplet | result taxon | group defined here | note

Each lead has either a "go to" couplet or a result taxon. Two results in one lead are separated by ;. Couplet ids may have letters (P1, S12, F3) for keys with separate sections.

Rebuild

pip install pymupdf                 # only needed for figure extraction
python scripts/extract_figures.py   # optional: re-extract figures from the CC BY PDFs
python scripts/build_data.py        # transcriptions -> data/keys.csv, with checks
python scripts/build_site.py        # data/*.csv -> site/

build_data.py stops with a list of problems if a couplet lacks a lead, a "go to" points nowhere, a couplet cannot be reached, or a result taxon is missing from taxa.csv.

Principles

  • Keys are never "corrected" in place. Printing errors are fixed only when certain (e.g. Lewis 1978 couplet 1b), with the original wording in the note and a row in conflicts.csv.
  • Results use current names; the name printed in the source is given in the note.
  • Species described after a key (e.g. P. shadenae, S. raynali) are linked from the leads where a user would otherwise reach the older name.
  • Figures are reproduced only from CC BY 4.0 publications, with attribution.

Offline use and installing as an app

Open the website once with an internet connection and keep the page open until the green label in the header says ✓ Available offline (about 26 MB is saved in the browser). After that every page, key, figure and the glossary work without internet, at the same address. Links to other websites (journals, CDC, DOIs) still need a connection.

  • Install as an app: click ⤓ Install app in the header (Chrome, Edge, Android), or use the browser menu (Add to Home Screen on iPhone/iPad Safari). The app opens in its own window and also works offline.
  • Updates are downloaded automatically the next time the site is opened with internet; only changed files are downloaded. A notice offers to reload when a new version has been saved.
  • Open the site on each device before going to the field. Phones and tablets may delete the saved copy when storage is very low; installing the app makes this less likely.
  • A copy of the site/ folder opened from a USB stick also works offline (without the app features).

Technical: build_site.py writes site/sw.js (service worker, from scripts/assets/sw.template.js) with a list of every file and a content hash, and site/manifest.webmanifest. Nothing needs to be done by hand.

Publishing

The site/ folder is a complete static website. On GitHub: Settings → Pages → deploy from branch, folder /site (or copy it to a docs/ folder). Do not commit the source PDFs to a public repository; most are copyrighted (they are excluded by .gitignore).
